📊 SQLite Window Functions

Advanced Analytics with Partitions, Ranking & Aggregation

📋 Module Overview

Window functions (also called analytic functions) allow you to perform calculations across rows related to the current row. Unlike aggregate functions that collapse rows, window functions preserve individual rows while adding computed values. This module covers partitions, ordering, framing, ranking functions, aggregate window functions, offset functions, chaining, and best practices for productive data analysis.

🎯 Core Concepts

What are Window Functions?
Window functions perform calculations across a set of rows (the "window") that are related to the current row. They return a value for each row, unlike aggregate functions which return a single value for a group. Window functions are essential for rankings, running totals, moving averages, and comparative analytics.

Basic Syntax

-- Window function syntax function_name(expression) OVER ( [PARTITION BY partition_expression] [ORDER BY sort_expression] [frame_clause] )

1. Partitions (PARTITION BY)

Understanding Partitions
PARTITION BY divides the result set into partitions (groups). The window function is applied separately to each partition. Think of it like GROUP BY, but without collapsing rows.
-- Create sample sales table CREATE TABLE sales ( id INTEGER PRIMARY KEY, department TEXT, employee TEXT, amount REAL, sale_date DATE ); INSERT INTO sales VALUES (1, 'IT', 'Alice', 5000, '2024-01-15'), (2, 'IT', 'Bob', 7000, '2024-01-20'), (3, 'Sales', 'Charlie', 9000, '2024-01-10'), (4, 'Sales', 'David', 6000, '2024-01-25'), (5, 'IT', 'Eve', 8000, '2024-02-05'); -- Calculate total sales per department for each employee SELECT employee, department, amount, SUM(amount) OVER (PARTITION BY department) AS dept_total FROM sales; /* Result: employee | department | amount | dept_total ---------|------------|--------|------------ Alice | IT | 5000 | 20000 Bob | IT | 7000 | 20000 Eve | IT | 8000 | 20000 Charlie | Sales | 9000 | 15000 David | Sales | 6000 | 15000 */

2. Ordering (ORDER BY)

Window Ordering
ORDER BY within a window determines the order of rows for the window function. It's separate from the query's main ORDER BY. This is crucial for ranking and running calculations.
-- Rank employees by sales within each department SELECT employee, department, amount, ROW_NUMBER() OVER ( PARTITION BY department ORDER BY amount DESC ) AS rank_in_dept FROM sales; /* Result: employee | department | amount | rank_in_dept ---------|------------|--------|------------- Eve | IT | 8000 | 1 Bob | IT | 7000 | 2 Alice | IT | 5000 | 3 Charlie | Sales | 9000 | 1 David | Sales | 6000 | 2 */

3. Framing (Frame Clause)

Understanding Frames
The frame clause defines which rows around the current row are included in the window. Frames are essential for moving averages, running totals, and calculations relative to the current row.
-- Frame syntax options ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW -- All rows from start to current ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING -- Current to end ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING -- 1 before, current, 1 after ROWS BETWEEN 2 PRECEDING AND CURRENT ROW -- 2 before and current -- Calculate running total of sales SELECT employee, sale_date, amount, SUM(amount) OVER ( ORDER BY sale_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW ) AS running_total FROM sales; -- 3-day moving average SELECT sale_date, amount, AVG(amount) OVER ( ORDER BY sale_date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW ) AS moving_avg_3day FROM sales;

📊 Window Function Types

1. Ranking Functions

ROW_NUMBER(), RANK(), DENSE_RANK()
Ranking functions assign a rank or number to each row within a partition. They differ in how they handle ties.
Function Description Handles Ties
ROW_NUMBER() Unique sequential number for each row No gaps, arbitrary order for ties
RANK() Rank with gaps after ties Same rank, skips next numbers
DENSE_RANK() Rank without gaps Same rank, no gaps
NTILE(n) Divide rows into n groups Distributes evenly
-- Compare ranking functions CREATE TABLE scores ( student TEXT, score INTEGER ); INSERT INTO scores VALUES ('Alice', 95), ('Bob', 90), ('Charlie', 90), -- Tie ('David', 85), ('Eve', 80); SELECT student, score, ROW_NUMBER() OVER (ORDER BY score DESC) AS row_num, RANK() OVER (ORDER BY score DESC) AS rank, DENSE_RANK() OVER (ORDER BY score DESC) AS dense_rank, NTILE(2) OVER (ORDER BY score DESC) AS quartile FROM scores; /* Result: student | score | row_num | rank | dense_rank | quartile ---------|-------|---------|------|------------|---------- Alice | 95 | 1 | 1 | 1 | 1 Bob | 90 | 2 | 2 | 2 | 1 Charlie | 90 | 3 | 2 | 2 | 1 David | 85 | 4 | 4 | 3 | 2 Eve | 80 | 5 | 5 | 4 | 2 */

2. Aggregate Window Functions

SUM, AVG, COUNT, MIN, MAX as Window Functions
Standard aggregate functions can be used as window functions with OVER clause. They calculate across the window frame instead of collapsing rows.
-- Running total and cumulative average SELECT sale_date, amount, SUM(amount) OVER ( ORDER BY sale_date ROWS UNBOUNDED PRECEDING ) AS running_total, AVG(amount) OVER ( ORDER BY sale_date ROWS UNBOUNDED PRECEDING ) AS cumulative_avg, COUNT(*) OVER ( ORDER BY sale_date ROWS UNBOUNDED PRECEDING ) AS row_count FROM sales; -- Percentage of department total SELECT employee, department, amount, ROUND(amount * 100.0 / SUM(amount) OVER (PARTITION BY department), 2) AS pct_of_dept FROM sales; -- Compare to department average SELECT employee, amount, AVG(amount) OVER (PARTITION BY department) AS dept_avg, amount - AVG(amount) OVER (PARTITION BY department) AS diff_from_avg FROM sales;

3. Offset Functions

LAG, LEAD, FIRST_VALUE, LAST_VALUE
Offset functions access values from other rows relative to the current row without self-joins. Perfect for comparing current vs previous values, trends, and time-series analysis.
-- LAG: Access previous row SELECT sale_date, amount, LAG(amount) OVER (ORDER BY sale_date) AS prev_amount, amount - LAG(amount) OVER (ORDER BY sale_date) AS change FROM sales; -- LEAD: Access next row SELECT sale_date, amount, LEAD(amount) OVER (ORDER BY sale_date) AS next_amount, LEAD(sale_date) OVER (ORDER BY sale_date) AS next_date FROM sales; -- LAG with offset and default SELECT sale_date, amount, LAG(amount, 2, 0) OVER (ORDER BY sale_date) AS amount_2_days_ago FROM sales; -- FIRST_VALUE and LAST_VALUE SELECT employee, department, amount, FIRST_VALUE(amount) OVER ( PARTITION BY department ORDER BY amount DESC ) AS highest_in_dept, LAST_VALUE(amount) OVER ( PARTITION BY department ORDER BY amount DESC ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ) AS lowest_in_dept FROM sales;

4. Window Function Chaining

Combining Multiple Window Functions
You can use multiple window functions in the same query, or use window functions on top of other window functions via subqueries for complex analytics.
-- Multiple window functions in one query SELECT employee, department, amount, RANK() OVER (PARTITION BY department ORDER BY amount DESC) AS dept_rank, RANK() OVER (ORDER BY amount DESC) AS overall_rank, SUM(amount) OVER (PARTITION BY department) AS dept_total, AVG(amount) OVER () AS company_avg FROM sales; -- Nested window functions via subquery WITH ranked_sales AS ( SELECT employee, department, amount, RANK() OVER (PARTITION BY department ORDER BY amount DESC) AS dept_rank FROM sales ) SELECT employee, department, amount, dept_rank, AVG(amount) OVER (PARTITION BY dept_rank) AS avg_for_same_rank FROM ranked_sales;

🎯 Real-World Use Cases

Use Case 1: Top N per Group

-- Find top 2 salespeople in each department WITH ranked AS ( SELECT employee, department, amount, ROW_NUMBER() OVER ( PARTITION BY department ORDER BY amount DESC ) AS rn FROM sales ) SELECT employee, department, amount FROM ranked WHERE rn <= 2;

Use Case 2: Running Statistics Dashboard

-- Sales dashboard with multiple metrics SELECT sale_date, amount, -- Running total SUM(amount) OVER ( ORDER BY sale_date ROWS UNBOUNDED PRECEDING ) AS ytd_total, -- 7-day moving average AVG(amount) OVER ( ORDER BY sale_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW ) AS moving_avg_7d, -- Day-over-day change amount - LAG(amount) OVER (ORDER BY sale_date) AS daily_change, -- Percentage change ROUND( (amount - LAG(amount) OVER (ORDER BY sale_date)) * 100.0 / LAG(amount) OVER (ORDER BY sale_date), 2 ) AS pct_change FROM sales;

Use Case 3: Gap Analysis

-- Find gaps in sequential data WITH sequenced AS ( SELECT id, LAG(id) OVER (ORDER BY id) AS prev_id FROM sales ) SELECT prev_id + 1 AS gap_start, id - 1 AS gap_end FROM sequenced WHERE id - prev_id > 1;

Use Case 4: Percentile Analysis

-- Divide into quartiles and analyze SELECT employee, amount, NTILE(4) OVER (ORDER BY amount) AS quartile, CASE NTILE(4) OVER (ORDER BY amount) WHEN 1 THEN 'Bottom 25%' WHEN 2 THEN '2nd Quartile' WHEN 3 THEN '3rd Quartile' WHEN 4 THEN 'Top 25%' END AS performance_tier FROM sales;

✅ Best Practices for Productive Analysis

✅ Window Function Best Practices:

1. Performance Optimization:
• Create indexes on columns used in PARTITION BY and ORDER BY
• Use PARTITION BY to limit window size
• Avoid unnecessary window functions—materialize results in CTEs if reused
• Use specific frame clauses instead of default to improve performance

2. Code Clarity:
• Use CTEs to break complex window function queries into readable steps
• Name window functions descriptively (running_total vs rt)
• Add comments for complex frame definitions
• Reuse window definitions with WINDOW clause

3. Correctness:
• Remember LAST_VALUE needs explicit frame to UNBOUNDED FOLLOWING
• Be careful with NULL handling in ORDER BY (NULLs sort first by default)
• Test edge cases: empty partitions, single-row partitions, all NULLs
• Verify frame boundaries match your analytical intent

4. Maintainability:
• Use named windows for repeated window specifications
• Document business logic in comments
• Create views for commonly used window calculations
• Test with small datasets before production

Using WINDOW Clause (Named Windows)

-- Define reusable window specifications SELECT employee, department, amount, RANK() OVER w AS dept_rank, SUM(amount) OVER w AS running_total, AVG(amount) OVER w AS running_avg FROM sales WINDOW w AS (PARTITION BY department ORDER BY sale_date);

⚠️ Common Pitfalls & Troubleshooting

Common Window Function Mistakes:

1. LAST_VALUE doesn't show expected result:
Problem: Default frame is RANGE UNBOUNDED PRECEDING AND CURRENT ROW
Solution: Explicitly use ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING

2. Unexpected ordering with NULLs:
Problem: NULLs sort first in ascending order
Solution: Use NULLS LAST in ORDER BY clause

3. Performance degradation:
Problem: Large windows without proper indexing
Solution: Add indexes on PARTITION BY and ORDER BY columns

4. Confusion between ROWS and RANGE:
• ROWS: Physical rows based on position
• RANGE: Logical range based on value (default)
Use ROWS for most cases unless you need value-based framing

5. Mixing window and non-window columns:
Problem: All columns must be either aggregated or in GROUP BY
Solution: Use window functions OR aggregates, wrap in CTEs if combining

📊 Performance Tips

-- Create indexes for better performance CREATE INDEX idx_sales_dept_date ON sales(department, sale_date); CREATE INDEX idx_sales_date ON sales(sale_date); -- Materialize intermediate results in CTE WITH daily_stats AS ( SELECT sale_date, SUM(amount) AS daily_total FROM sales GROUP BY sale_date ) SELECT sale_date, daily_total, SUM(daily_total) OVER (ORDER BY sale_date) AS running_total FROM daily_stats; -- Use EXPLAIN QUERY PLAN to understand execution EXPLAIN QUERY PLAN SELECT employee, RANK() OVER (PARTITION BY department ORDER BY amount DESC) FROM sales;
