💾 Storage Options for Dates and Times

Choosing the Right Storage Format
SQLite does not have a dedicated DATE or DATETIME type. Instead, use type affinity to store temporal data as TEXT, REAL, or INTEGER. Each format has trade-offs in readability, precision, and performance. Choose based on your application's needs for sorting, arithmetic, or human readability.
Storage Class Format Pros Cons Use Case
TEXT ISO 8601 (e.g., '2026-01-05 12:34:56') Human-readable, sortable as strings, supports timezones Slower arithmetic, larger storage Logs, user-facing dates, when readability matters
REAL Julian day number (e.g., 2460825.5 for noon on 2026-01-05) High precision (fractional days), easy date differences Not human-readable, floating-point precision issues Scientific calculations, historical dates
INTEGER Unix timestamp (seconds since 1970-01-01 UTC) Compact, fast arithmetic and comparisons, efficient indexing Limited to post-1970 accurately, no subsecond precision natively Modern apps, timestamps in logs or events
-- Example table with different storage CREATE TABLE events ( id INTEGER PRIMARY KEY, event_date TEXT, -- ISO format julian_time REAL, -- Julian day unix_stamp INTEGER -- Unix epoch ); -- Insert current time in all formats INSERT INTO events (event_date, julian_time, unix_stamp) VALUES ( datetime('now'), julianday('now'), unixepoch('now') );
✅ Best Practice:
• Use TEXT for most cases due to readability and compatibility with ISO standards.
• For performance-critical apps with frequent date math, prefer INTEGER (Unix timestamps).
• Always store in UTC to avoid timezone confusion; convert to local on display.

🛠️ Core Functions

date(timestring, modifiers...)

date Function
Returns the date in YYYY-MM-DD format. Useful for extracting or computing dates without time components. Supports all time strings and modifiers.
-- Basic usage SELECT date('2026-01-05 12:34:56') AS extracted_date; -- '2026-01-05' -- With modifiers SELECT date('now', '-3 months', 'start of month') AS quarter_start; -- Real-world: Find birthdays this month SELECT name FROM users WHERE date(birthdate, 'start of month') = date('now', 'start of month');

time(timestring, modifiers...)

time Function
Returns the time in HH:MM:SS format. Ideal for time-only extractions or adjustments.
-- Extract time SELECT time('2026-01-05 12:34:56') AS extracted_time; -- '12:34:56' -- Adjust time SELECT time('now', '+2 hours', 'localtime') AS adjusted_local; -- Real-world: Schedule reminders SELECT task FROM reminders WHERE time(reminder_time) BETWEEN time('now', 'localtime') AND time('now', '+1 hour', 'localtime');

datetime(timestring, modifiers...)

datetime Function
Returns full datetime in YYYY-MM-DD HH:MM:SS format. Versatile for complete timestamps.
-- Current datetime SELECT datetime('now', 'localtime') AS local_now; -- Convert formats SELECT datetime(2460825.5, 'julianday') AS from_julian; -- Real-world: Log entry with offset INSERT INTO logs (timestamp, message) VALUES (datetime('now', '+5 hours'), 'Event in future timezone');

julianday(timestring, modifiers...)

julianday Function
Returns Julian day number as REAL. Excellent for precise date differences.
-- Current Julian day SELECT julianday('now'); -- Difference in days SELECT julianday('2026-01-05') - julianday('2000-01-01') AS days_diff; -- Real-world: Project duration SELECT project_name, round(julianday(end_date) - julianday(start_date)) AS duration_days FROM projects WHERE duration_days > 365;

unixepoch(timestring, modifiers...)

unixepoch Function
Returns Unix timestamp as INTEGER (seconds since 1970). Supports subsecond with 'subsec'.
-- Current Unix epoch SELECT unixepoch('now'); -- With subseconds SELECT unixepoch('now', 'subsec') AS precise; -- Real-world: Session timeout UPDATE sessions SET expired = 1 WHERE unixepoch('now') - unixepoch(last_active) > 3600; -- 1 hour

strftime(format, timestring, modifiers...)

strftime Function
Formats timestamps as TEXT. Supports various placeholders for year, month, etc.
-- Custom format SELECT strftime('%d/%m/%Y %H:%M', 'now') AS eu_format; -- Extract parts SELECT strftime('%Y', order_date) AS year FROM orders; -- Real-world: Monthly reports SELECT strftime('%Y-%m', order_date) AS month, SUM(amount) AS total_sales FROM orders GROUP BY month ORDER BY month DESC;

timediff(timestring1, timestring2)

timediff Function
Returns human-readable difference as ±YYYY-MM-DD HH:MM:SS.SSS. No modifiers.
-- Basic diff SELECT timediff('2026-01-05 12:00:00', '2000-01-01 00:00:00'); -- Real-world: Uptime calculation SELECT timediff('now', start_time) AS uptime FROM servers;

🔧 Time Strings and Modifiers

Supported Time Strings:
• YYYY-MM-DD, YYYY-MM-DD HH:MM, YYYY-MM-DD HH:MM:SS, YYYY-MM-DD HH:MM:SS.SSS
• YYYY-MM-DDTHH:MM:SS (ISO with T)
• HH:MM, HH:MM:SS, HH:MM:SS.SSS (assumes 2000-01-01)
• 'now'
• DDDDDDDDDD (Julian day or Unix timestamp with 'auto')
• With timezone: ±HH:MM or Z
Common Modifiers
±NNN units (years, months, days, hours, minutes, seconds)
start of year/month/day
weekday N (0=Sunday)
unixepoch, julianday, auto
localtime, utc
subsec
floor/ceiling (for invalid dates)
Modifier Examples
SELECT datetime('now', '+1 year', 'start of year');
SELECT date('2024-02-30', 'floor'); -- 2024-02-29

🎯 Real-World Use Cases

Use Case 1: E-commerce Order Analytics

-- Weekly sales report SELECT strftime('%Y-W%W', order_date) AS week, SUM(amount) AS total FROM orders GROUP BY week HAVING date(order_date) BETWEEN date('now', '-1 year') AND date('now');

Use Case 2: User Activity Tracking

-- Inactive users (last login > 30 days) SELECT username FROM users WHERE julianday('now') - julianday(last_login) > 30;

Use Case 3: Scheduling System

-- Next business day (skip weekends) SELECT date('now', '+1 day', CASE strftime('%w', 'now', '+1 day') WHEN '0' THEN '+1 day' -- Sunday to Monday WHEN '6' THEN '+2 days' -- Saturday to Monday ELSE '0 days' END) AS next_business_day;

✅ Best Practices & Optimizations

  • Store in UTC, display in local: Avoid timezone bugs
  • Index temporal columns for range queries
  • Use dedicated functions over strftime for precision
  • Batch computations in views or triggers for efficiency
  • Handle NULLs with COALESCE in queries

⚠️ Troubleshooting

Common Issues:
• Invalid formats return NULL: Validate with json_valid or patterns
• Timezone mismatches: System-dependent; test across OS
• Precision loss: Use 'subsec' for milliseconds
• Edge dates: Test leap years, year 2038 for Unix
