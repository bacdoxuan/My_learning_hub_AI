⚡ SQLite3 Triggers

Automate Actions with Database Triggers & Event Handling

📋 Module Overview

This module covers SQLite triggers—automated actions that fire in response to INSERT, UPDATE, or DELETE events. You'll learn trigger syntax, timing (BEFORE/AFTER), access to OLD/NEW values, practical use cases like auditing and validation, best practices for performance and maintainability, troubleshooting techniques, and how to avoid common pitfalls like infinite loops and cascading changes.

🛠️ Trigger Fundamentals

What are Triggers?
Triggers are database objects that automatically execute SQL statements when specific events (INSERT, UPDATE, DELETE) occur on a table. They enforce business rules, maintain data integrity, and automate repetitive tasks without application-level code.

Basic Trigger Syntax

-- Basic CREATE TRIGGER syntax CREATE TRIGGER trigger_name [BEFORE | AFTER] [INSERT | UPDATE | DELETE] ON table_name [FOR EACH ROW] [WHEN condition] BEGIN -- trigger statements END;

Trigger Timing

Timing Description Use Case
BEFORE Executes before the triggering event Validation, data modification
AFTER Executes after the triggering event Auditing, cascade updates
INSTEAD OF Replaces the triggering event (views only) Make views updatable

🎯 Trigger Types & Examples

INSERT Triggers

Auto-Generate Timestamps
Automatically set created_at timestamp when a new row is inserted.
-- Create users table CREATE TABLE users ( id INTEGER PRIMARY KEY, username TEXT NOT NULL, email TEXT UNIQUE, created_at TEXT, updated_at TEXT ); -- Trigger to set created_at on INSERT CREATE TRIGGER set_user_created_at AFTER INSERT ON users BEGIN UPDATE users SET created_at = datetime('now'), updated_at = datetime('now') WHERE id = NEW.id; END;

UPDATE Triggers

Track Last Modified Time
Update the updated_at column whenever a row is modified.
-- Trigger to update updated_at on UPDATE CREATE TRIGGER set_user_updated_at AFTER UPDATE ON users BEGIN UPDATE users SET updated_at = datetime('now') WHERE id = NEW.id; END;

DELETE Triggers

Audit Trail
Log deletions to an audit table before removing data.
-- Create audit table CREATE TABLE user_audit ( audit_id INTEGER PRIMARY KEY AUTOINCREMENT, user_id INTEGER, username TEXT, action TEXT, deleted_at TEXT ); -- Trigger to log deletions CREATE TRIGGER log_user_deletion BEFORE DELETE ON users BEGIN INSERT INTO user_audit (user_id, username, action, deleted_at) VALUES (OLD.id, OLD.username, 'DELETE', datetime('now')); END;

🔍 OLD and NEW Values

Understanding Context Variables:
• NEW: Available in INSERT and UPDATE triggers, contains the new row values
• OLD: Available in UPDATE and DELETE triggers, contains the old row values
• Access columns with NEW.column_name or OLD.column_name
-- Track specific column changes CREATE TABLE price_history ( id INTEGER PRIMARY KEY AUTOINCREMENT, product_id INTEGER, old_price REAL, new_price REAL, changed_at TEXT ); CREATE TRIGGER track_price_changes AFTER UPDATE OF price ON products WHEN OLD.price != NEW.price BEGIN INSERT INTO price_history (product_id, old_price, new_price, changed_at) VALUES (NEW.id, OLD.price, NEW.price, datetime('now')); END;

🎯 Real-World Use Cases

Use Case 1: Data Validation

-- Prevent negative inventory CREATE TRIGGER prevent_negative_inventory BEFORE UPDATE OF quantity ON inventory WHEN NEW.quantity < 0 BEGIN SELECT RAISE(ABORT, 'Inventory quantity cannot be negative'); END;

Use Case 2: Cascade Updates

-- Update order totals when items change CREATE TRIGGER update_order_total AFTER INSERT ON order_items BEGIN UPDATE orders SET total_amount = ( SELECT SUM(price * quantity) FROM order_items WHERE order_id = NEW.order_id ) WHERE id = NEW.order_id; END;

Use Case 3: Soft Deletes

-- Implement soft delete pattern CREATE TRIGGER soft_delete_user INSTEAD OF DELETE ON users_view BEGIN UPDATE users SET deleted_at = datetime('now'), is_active = 0 WHERE id = OLD.id; END;

🔧 Managing Triggers

List All Triggers

-- View all triggers in database SELECT name, tbl_name, sql FROM sqlite_master WHERE type = 'trigger';

Drop Triggers

-- Remove a trigger DROP TRIGGER IF EXISTS trigger_name;

Disable/Enable Triggers

Note: SQLite doesn't have built-in DISABLE/ENABLE commands. To temporarily disable triggers, you must DROP and recreate them, or use conditional logic within the trigger.

✅ Best Practices & Optimizations

✅ Key Recommendations:
• Keep triggers simple: Complex logic should be in application code or stored procedures
• Use WHEN clause: Filter trigger execution for better performance
• Avoid recursive triggers: SQLite doesn't support recursive triggers by default
• Document thoroughly: Comment trigger purpose and logic clearly
• Test edge cases: Verify behavior with NULL values, constraints, transactions
• Consider performance: Triggers fire for every row; optimize for bulk operations
• Use specific columns: UPDATE OF column is more efficient than general UPDATE

⚠️ Troubleshooting

Common Issues:
• Infinite loops: Ensure triggers don't modify the same table in ways that retrigger themselves
• Transaction conflicts: Triggers run within the same transaction—failures roll back everything
• OLD/NEW access: Remember OLD is not available for INSERT, NEW not available for DELETE
• RAISE() errors: Use SELECT RAISE(ABORT, 'message') to stop execution with error
• Performance: Too many triggers or complex logic can slow down DML operations
• Debugging: Use audit tables or temporary logging to trace trigger execution
