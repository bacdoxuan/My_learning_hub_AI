🛠️ Core String Functions

Understanding String Handling in SQLite
Strings in SQLite are stored as TEXT with UTF-8 encoding by default. Functions operate on Unicode characters, but performance can vary with large strings or complex operations. Always consider collation (case sensitivity) when searching or comparing—use NOCASE for case-insensitive indexes.

Concatenation

concat & || Operator
Joins multiple strings. The || operator is binary; concat() (SQLite 3.44+) handles multiple arguments. Useful for building full names, paths, or dynamic queries.
-- Using || operator SELECT first_name || ' ' || last_name AS full_name FROM employees; -- Using concat() for multiple strings SELECT concat(street, ', ', city, ', ', state, ' ', zip) AS address FROM customers; -- Real-world: Generating URLs SELECT concat('https://example.com/user/', id, '/', lower(username)) AS profile_url FROM users;

Case Conversion

upper & lower
Converts strings to uppercase or lowercase. Essential for normalization in searches or comparisons.
-- Normalize emails UPDATE users SET email = lower(email); -- Case-insensitive search SELECT * FROM products WHERE lower(name) LIKE '%widget%'; -- Real-world: Standardizing tags INSERT INTO tags (tag_name) VALUES (upper('Important'));

Length & Trimming

length, trim, ltrim, rtrim
length returns character count; trim removes characters from both ends (default spaces). ltrim/rtrim for one side. Great for data cleaning.
-- Get string length SELECT name, length(name) AS name_length FROM users WHERE length(name) > 20; -- Trim spaces UPDATE addresses SET street = trim(street); -- Custom trim (remove prefixes/suffixes) SELECT ltrim(phone, '+1-') AS cleaned_phone FROM contacts; -- Real-world: Validate input length after trim SELECT * FROM comments WHERE length(trim(text)) < 5; -- Find short comments

Substring Extraction & Search

substr & instr
substr extracts parts; instr finds position of substring. Combine for parsing.
-- Extract domain from email SELECT substr(email, instr(email, '@') + 1) AS domain FROM users; -- Parse log messages SELECT substr(message, 1, instr(message, ':') - 1) AS level FROM logs; -- Real-world: Extract year from date string SELECT substr(publish_date, 1, 4) AS year FROM articles GROUP BY year;

Replacement

replace
Replaces all occurrences of a substring. Useful for sanitization or formatting.
-- Clean phone numbers UPDATE contacts SET phone = replace(replace(phone, '-', ''), ' ', ''); -- Censor words SELECT replace(content, 'badword', '***') AS censored FROM posts; -- Real-world: Normalize paths SELECT replace(file_path, '\\', '/') AS unix_path FROM files;

Formatting

printf
Formats strings with placeholders. Like C's printf, for precise output.
-- Format numbers SELECT printf('%.2f USD', amount) AS formatted_amount FROM transactions; -- Padded strings SELECT printf('%010d', id) AS padded_id FROM invoices; -- Real-world: Generate codes SELECT printf('ORD-%s-%04d', strftime('%Y', order_date), id) AS order_code FROM orders;

Advanced Utilities

hex, quote, unicode, soundex
hex for binary to hex; quote escapes for SQL; unicode gets code point; soundex for phonetic matching.
-- Hex encoding SELECT hex(blob_data) AS hex_string FROM binaries; -- Safe quoting SELECT quote(user_input) AS safe_input; -- Unicode point SELECT unicode(substr(name, 1, 1)) AS first_char_code FROM names; -- Soundex matching SELECT * FROM names WHERE soundex(name) = soundex('Smith');

🎯 Real-World Use Cases

Use Case 1: User Data Cleaning

-- Clean and normalize user profiles UPDATE profiles SET bio = trim(replace(bio, '\n', ' ')), display_name = concat(upper(substr(first_name, 1, 1)), lower(substr(first_name, 2)));

Use Case 2: Log Parsing

-- Extract IP from log SELECT substr(log_line, instr(log_line, 'IP:') + 3, 15) AS ip FROM access_logs;

Use Case 3: Search Optimization

-- Phonetic search for names SELECT * FROM contacts WHERE soundex(last_name) = soundex('Smyth');

✅ Best Practices & Optimizations

✅ Key Recommendations:
• Normalize data early: Apply lower/trim on insert/update to avoid repeated computations.
• Avoid functions in WHERE for indexed columns: Pre-compute if possible (e.g., stored columns).
• Use parameterized queries: Prevent injection when building strings dynamically.
• Batch operations: Wrap multiple string updates in transactions for speed.
• Collation awareness: Use COLLATE NOCASE for case-insensitive comparisons.
• Performance: For very large strings, consider application-side processing.

⚠️ Troubleshooting

Common Issues:
• Unicode handling: Ensure database encoding is UTF-8; test with non-ASCII.
• Index prevention: Functions like upper() disable indexes—use views or computed columns.
• NULL propagation: Most functions return NULL on NULL input—use COALESCE.
• Length vs bytes: length() counts characters, not bytes—use octet_length for bytes.
